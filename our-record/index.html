Blind test

We test our method first, in public

Before we sell an examination, we test the method blind, and we release the results pass or fail. One round can't give a general error rate. It shows whether the method catches what it's built to catch. More rounds come after that.

I ask three questions of any check, starting with my own

Who wrote the list?

Not the vendor. Two lists, built apart. A red team plants problems in made-up evidence files, some outside both lists.

Do I pay more for a pass?

No. Every fee is set before the work starts, and a refusal pays the same.

Who can overrule the result?

Not me. A signer who wrote none of it applies the scoring rules. I can't overrule a refusal.

The blind test

Who sits where, and how the answer keys are kept

The builder is our co-founder. Every other seat is outside the company. Each person is named only after accepting in writing.

The cases are real failures from the Casebook, cases confirmed clean, and cases the red team builds with faults planted on purpose. Every case has an answer key, sealed before the run and held by the red team. The signer holds only each key's fingerprint, a code that shows whether the key was changed.

The inspectors file straight with the signer. Only after both have filed are the keys opened, checked against their fingerprints and used to score. Then we release the cases, the keys and the results.

Every planted fault an inspector misses counts against the method, and so does every fault called in a clean case. How closely the two inspectors must agree is set and sealed before the run.

I run the exam first. My run isn't blind, because I picked the real cases, so it's reported apart.
